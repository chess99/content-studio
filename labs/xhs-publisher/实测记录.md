## `xiaohongshu-mcp`

下载并解压了 Windows x64 预编译包，程序参数可正常读取：

```text
-bin string      浏览器二进制文件路径
-headless        是否无头模式，默认 true
-port string     默认 :18060
```

首次启动成功自动下载内置 Chromium `148.0.7778.215`，随后输出：

```text
Registered 13 MCP tools
MCP Server initialized with official SDK
启动 HTTP 服务器: :18061
```


## `post-to-xhs` Skill

仓库自带的 Skill 比 MCP 发布接口更贴近“检查后发布”：

```text
cdp_publish.py fill           # 填图片、标题、正文，不点发布
cdp_publish.py click-publish  # 用户确认后，单独点击发布
```

但当前原版存在环境兼容问题：

- 写死访问 `127.0.0.1:9222/json`。
- 当前 Codex 浏览器通过受控代理连接，原生 `/json`、`/json/list`、`/json/version` 均返回 404。
- 默认账号配置样例还硬编码了作者机器路径 `C:\Users\admin\...`。
- 因此本机实际 `check-login` 失败，不能直接把这个 Skill 当作现成答案。

正确的后续方向是保留它的“两阶段命令”设计，替换浏览器连接与账号配置层。

## `xhs-cli`

在独立 Python 3.12 虚拟环境中完成了本地源码安装，基础依赖安装成功，环境本身约 243.5 MiB，尚未包含 Camoufox 浏览器。

继续试用时出现两个独立问题：

1. `browser-cookie3` 没有从正在运行的 Chrome 中取得同时包含 `a1` 与 `web_session` 的小红书 Cookie。
2. `python -m camoufox fetch` 通过 GitHub API发现浏览器版本时被匿名 API 限流，三个上游源都返回 403，无法完成首次浏览器安装。

即使绕过下载问题，`xhs post` 的实现仍然在填完表单后直接寻找“发布”按钮并点击，没有 fill-only 或草稿参数。

## `social-auto-upload`

源码确认小红书 CLI 支持：

```text
sau xiaohongshu login --account <account>
sau xiaohongshu check --account <account>
sau xiaohongshu upload-note --account <account> --images ... --title ... --note ...
```

支持定时发布，但小红书 `upload-note` 没有 `--draft` 参数。源码中的 `--draft` 仅出现在腾讯视频上传分支，不能据此推断小红书也支持草稿。

该项目根目录同样没有 LICENSE 文件。

## 当前网页事实


检查后已关闭该后台标签页，没有操作用户已有标签页。这个事实只能证明网页版存在草稿箱，不能证明上述开源工具已实现可靠的草稿保存动作。
