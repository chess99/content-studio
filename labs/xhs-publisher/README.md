# 小红书发布工具实测

调研日期：2026-07-21

## 结论

当前最值得落地的是 **`xpzouying/xiaohongshu-mcp`**，但要明确两种不同目标：

1. **用户确认后，一次调用直接发布**：使用 MCP 的 `publish_content`。
2. **先把图片、标题和正文填进创作页，留给用户检查**：不能用现有 `publish_content`，因为它会点击发布。需要使用仓库附带 `post-to-xhs` Skill 的 fill-only 思路，或给 MCP 增加一个 `prepare_content` 工具。

现有候选都没有经过验证的“小红书服务端保存草稿”接口。当前创作页确实显示“草稿箱”，但本次检查的开源工具没有为小红书实现“保存草稿”命令。把表单留在浏览器里也不等于已可靠写入草稿箱。

因此，最合适的最终形态不是单一的 `publish(...)`，而是两个明确动作：

```text
prepare(title, content, images)  → 填表、预览、不发布
publish_prepared()               → 用户明确确认后才点击发布
```

如果暂时不开发适配层，则采用：

```text
本地 post.yaml → 人工审阅 → 明确确认 → MCP publish_content
```

## 实际试用结果

| 方案 | 实测结果 | 是否适合当前场景 |
|---|---|---|
| `xpzouying/xiaohongshu-mcp` | Windows 预编译版安装成功；服务启动成功；MCP 初始化成功；发现 13 个工具；健康检查、登录检查、二维码获取均成功；独立登录态当前为未登录 | **首选发布器**。需扫码一次；现有发布工具会直接发布，不负责保存草稿 |
| 仓库内 `post-to-xhs` Skill | 源码提供 `fill` 与 `click-publish` 两阶段，能力模型最贴近“先检查再发布”；但原版写死访问 Chrome 原生 `127.0.0.1:9222/json`，在当前 Codex 受控 Chrome 环境返回 404，无法原样运行 | **值得改造成适配层**，当前不能直接用 |
| `jackwener/xhs-cli` | Python 包安装成功；未能从正在运行的本机 Chrome 提取所需 Cookie；Camoufox 浏览器下载又被 GitHub API 限流阻断 | 不作为首选。安装链更重，首次运行失败点更多，且 `post` 同样直接点击发布 |
| `dreammis/social-auto-upload` | 已克隆并核对当前源码；确有 `sau xiaohongshu upload-note`、多账号、定时发布；小红书分支没有 `--draft`，草稿参数只用于腾讯视频分支 | 只有以后需要多平台、多账号、定时发布时再考虑 |
| `lucasygu/redbook` | 源码与 README 明确承认发布经常触发 `type=124` 验证码，图片上传能成功但最终发布不稳定 | 不作为发布器 |

本次没有创建草稿或发布测试笔记，也没有调用任何会改变账号内容的写操作。

## 为什么 MCP 仍然是首选

- 发布动作被封装成结构化工具，Codex 不需要每次重新识别网页。
- 本地绝对路径图片受支持，适合现有 `D:\code\finance-content` 素材目录。
- 最新版本会逐张等待图片预览，并在点击发布后回读成功页面，减少“点了按钮就误报成功”。
- Windows 有预编译程序，实际已经在本机跑通服务、MCP 协议和二维码链路。
- 可把发布工具设置为每次人工审批，避免未经确认直接发布。

局限也很明确：

- 它使用自己的浏览器和 Cookie，不会自动复用日常 Chrome 登录态。
- 第一次需要扫码登录，且网页端多处登录可能互相踢下线。
- `publish_content` 是立即发布动作，不是草稿动作。
- 项目根目录没有 LICENSE 文件；个人本机试用问题较小，但二次分发或商业集成前需要向作者确认授权。
- 预编译程序首次从项目自建 CDN 下载浏览器；虽然源码内有 SHA-256 校验，仍应把它视为第三方供应链依赖。

## 推荐工作流

```text
1. 素材继续保存在 finance-content/<选题>/
2. 用 post.yaml 固化标题、正文、图片顺序和状态
3. 发布前校验标题长度、正文长度、图片存在性和顺序
4. 向用户展示完整发布清单
5. 用户明确回复“确认发布”
6. 调用一次 publish_content
7. 记录返回结果；失败时保留本地 post.yaml 便于重试
```

建议权限规则：

- `check_login_status`、`get_login_qrcode`：允许调用。
- `publish_content`：每次必须人工确认。
- 点赞、收藏、评论、回复、删除 Cookie：默认禁用或每次确认。
- Cookie 和浏览器 profile：只保存在本机，永不进入 Git。
