# 主题系统参考

`wx-publisher` 的主题系统分成两个层级：少量完整预设用于快速选择，版式与调色板用于按需自定义。组合不会被包装成几十个需要记忆的“主题”。机器可读目录见 [`theme-palette-reference.json`](./theme-palette-reference.json)。

最后更新：2026-08-18。

## 产品原则

- 所有主题都使用纯白正文画布，与公众号固定的白色标题区和页面边缘连续衔接。
- 完整预设必须有清楚且独特的使用理由，不能只是颜色排列组合。
- 自定义只暴露两个高价值决策：信息结构选“版式”，视觉语气选“调色板”。
- 正文统一使用 `16px`、`line-height: 1.82`、段后 `16px` 的阅读基线；主题重点影响标题、强调、引用、代码、表格与高级模块。
- 颜色只承担导航、标记和状态功能，不承担整页氛围；标题不使用实色底、渐变底或阴影。
- 高级模块主体同样使用白色、细边框和规则线；浅色只用于标签、状态和极小面积提示，不使用装饰性渐变或悬浮阴影。
- 普通文字与白色背景至少满足 WCAG AA `4.5:1` 对比度。

## 六个完整预设

| ID | 展示名 | 定位 |
| --- | --- | --- |
| `default` | 基础白 | 最低干扰的通用默认方案 |
| `wechat-native` | 微信原生 | 熟悉稳妥的公众号气质 |
| `github-readme` | 技术简报 | 技术教程、产品说明与开发文档 |
| `nyt-classic` | 深度阅读 | 深度报道、评论、研究与长文 |
| `ink-minimal` | 墨线札记 | 文字密集、黑白克制的随笔与书评 |
| `warm-editorial` | 人文暖调 | 叙事、人物、访谈与生活方式 |

六个预设全部属于可靠方案，Studio 直接展示。旧有的 `chinese`、`bauhaus-primary`、`cyber` 已移除：它们主要依赖纸张底色、实色标题块或渐变氛围，放入公众号外壳后整体感较弱。

## 自定义主题

四种版式：

| ID | 展示名 | 结构特征 |
| --- | --- | --- |
| `clean` | 清爽 | 无底色标题与细分隔线 |
| `centered` | 居中 | 居中标题与上下规则线 |
| `editorial` | 刊物 | 左侧标记线与明确层级 |
| `poster` | 信号 | 顶部粗线与大字标题，无实色底 |

六套调色板：`neutral` 中性黑、`blue` 专业蓝、`green` 稳健绿、`red` 信号红、`warm` 陶土、`purple` 编辑紫。调色板只改变强调色，不改变白色画布。

## 设计依据

- [W3C 中文排版需求（CLREQ）](https://www.w3.org/TR/clreq/)：中文字符与标点以完整方形排版单元组织，因此正文保持系统中文字体优先，不额外增加字间距，也不靠拉宽字距制造“设计感”。
- [WCAG 2.2 对比度最低要求](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)：普通文字至少 `4.5:1`，大字至少 `3:1`。内置主题的正文和文字强调色按普通文字标准检查。
- 微信公众号客户端的文章标题、作者信息、正文两侧边距与底部操作栏由平台控制。主题无法让这些区域跟随正文换底色，因此正文画布必须保持白色连续，主题识别集中在内容内部的层级与标记。

## 使用方式

CLI 的完整预设仍使用单一参数；自定义组合使用两个显式参数：

```bash
wxp convert --file article.md --theme github-readme
wxp convert --file article.md --layout editorial --palette blue
```

REST API 与 Studio 使用结构化选择，字符串主题不再接受：

```json
{ "theme": { "preset": "default" } }
```

```json
{ "theme": { "layout": "poster", "palette": "red" } }
```

`wxp themes` 分别返回 `presets`、`layouts`、`palettes` 和各自数量。外部主题 JSON 文件仍作为专家级入口存在，但不属于内置主题目录。

## 维护检查

- 预设、版式和调色板 ID 必须唯一，并与运行时顺序一致。
- 任一内置主题都不得引入有色画布、实色标题底、渐变标题底或标题阴影。
- 高级模块不得用大面积渐变或阴影制造层级，优先使用规则线、边框、留白和字重。
- 新增预设必须先证明它承担了现有六套无法覆盖的内容任务，不能仅换颜色或装饰。
- JSON 中颜色统一使用六位十六进制。
- 修改主题系统时同步更新运行时、Studio、CLI、REST API、静态画廊、机器参考和测试。
