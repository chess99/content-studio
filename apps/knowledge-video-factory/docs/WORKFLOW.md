# 知识视频生产工作流

## 阶段 1：输入与研究

每条视频在外部内容资产仓库中建立独立 `TOPIC_DIR/video/`。输入至少包括原始内容、来源清单与图表数据。先区分事实、观点和推断，再压缩成视频 brief。

## 阶段 2：脚本

口播稿同时保存展示文字与朗读文字。事实性句子必须附 `sourceIds`，专业缩写通过品牌发音词典转换。脚本通过人工确认后，才能调用付费配音或素材服务。

## 阶段 3：分镜

先读取外部内容仓库的 `brand/BRAND.md`，再按项目选择 `themes/` 中的视觉预设，并优先从注册模板中选择画面。账号品牌控制作者识别、栏目和签名；视觉预设只控制版式、图表与动效，不能覆盖母品牌。每个场景包含口播、来源、视觉模板、数据引用、强调信息和时长策略。允许少量自定义镜头，但不能破坏统一视觉语言。

## 阶段 4：配音与字幕

逐场景生成配音，读取真实音频时长后再确定时间线。某场景返工时只重做该场景。服务提供可靠时间戳时保存原始边界信息；否则按人工拆分的 `captionChunks` 在真实音频时长内加权对齐。

当前正式默认适配器是 Fish Audio。项目模板默认使用 `s2.1-pro-free`、1.05 倍 API 语速和已验证的“自然流男”公开声线；开发和小规模生成可继续使用免费模型，大规模生产可切换为 `s2.1-pro`。公开声线正式商用前必须核实授权，长期应替换为权属明确的品牌声线。API key 只从 app 根目录 `.env` 读取。

脚本审核通过并将 `gates.scriptApproved` 设为 `true` 后，运行 `python scripts/generate-fish-project.py --project-dir <VIDEO_DIR>`。生成器直接读取项目 `config.json`，已有且大于 1KB 的音频会跳过，使用 `--force` 才统一重做。Fish 当前不提供本流程使用的词级时间戳，因此字幕使用 `captionChunks` 加权对齐。

本地 Qwen3-TTS 0.6B 是离线、零调用费兜底，已在 RTX 4060 Ti 8GB 上验证；Qwen 音频与 Fish 音频使用不同子目录，不互相覆盖。Edge Neural TTS 仅用于快速工程预览。公开 Hugging Face 演示脚本只用于同稿试听，不能作为生产依赖。

## 阶段 5：渲染

将分镜、音频、字幕、图表数据和模板组合为预览视频。当前主渲染器为 Remotion 4，画面组件位于 `src/video/`，但流程层仍通过结构化时间线传参，便于未来增加其他渲染后端。

## 阶段 6：质检

至少检查：

- 数字和事实是否有来源
- 图表值是否与输入数据一致
- 字幕、标题和图表是否越界或重叠
- 字体是否缺失
- 音频与场景是否同步
- 是否出现异常黑帧或过长静帧
- 画面、编码、帧率和音频参数是否符合平台要求

低清预览经人工确认后，才能生成正式成片。

当前 `video:qa` 已实现媒体参数、时长、来源、字幕边界、字幕长度、黑帧候选和音量检测，并为每个场景抽取中间帧。文字几何溢出检测仍是下一阶段工作。

## 阶段 7：发布包

输出视频、封面、字幕、标题候选、平台文案、标签、来源说明和免责声明。第一阶段只生成发布包，不自动上传。
