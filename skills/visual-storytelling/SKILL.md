# 视觉叙事

读取外部内容仓库的 `AGENTS.md` 与 `brand/BRAND.md`，确定 `TOPIC_DIR` 和用途。独立图片内容归入主题的 `image-post/`；文章插图归入 `longform/`；视频分镜归入 `video/`。按内容仓库现有规则组织，不另建平行资产库。

## 结构选择

- **信息图**：重点是关系。流程用有方向的步骤，比较用共同维度，层级用包含与从属，机制用部件和作用。先把逻辑画清，再选择视觉风格。阅读 [信息图](references/infographic.md)。
- **漫画**：重点是行动和变化。用人物的目的、尝试、结果传达知识；每格必须推进理解。阅读 [漫画](references/comic.md)。
- **精确图表、架构图**：数据与连线需要逐项控制时，用代码、矢量或标准绘图库生成；说明文字与插画可组合制作。

从用户已有目标和材料直接推导结构；无法判断核心关系时再澄清。不要为了展示风格库而让用户挑选几十个标签，也不要预设所有内容都适合卡片网格。

## 制作

先选择一个最难表达的局部验证结构、字体与画面密度，再扩展全图或整组。使用当前环境的原生生图工具；没有可用后端时说明缺项，并完成已可做的文案和构图设计。具体生成方法沿用 `image-post-workflow` 的图片质检要求，避免重复维护后端代码。

上游宝玉参考按需读取：`vendor/JimLiu/baoyu-skills/baoyu-infographic/` 与 `baoyu-comic/`。本工作区只复用其布局、画风和叙事参考；目录位置、品牌、工具调用和授权遵循本地工作流。不运行上游的偏好初始化或自动创建额外输出目录。

检查文字、数字、箭头、比例与因果关系；漫画额外检查人物、场景和道具连续性。查看原尺寸和手机缩略图。生成图片中的错误文字交给图片编辑工具修复或重新生成，不用程序覆盖原图文字。

交付可读的成图与后续复用必需的源文件。事实来源、提示词和角色设定留在制作文件，画面只呈现读者理解内容所需的信息。
