# 写作风格指南

这份指南定义博客文章的写作标准。主笔写初稿时遵循，同行审校时对照检查。

## 声音定位

**听起来像：** 一个在会后聚会上聊技术的资深工程师——有观点、有细节、带点不正经，真正懂行。

**不像：** 企业博客、新闻稿、PPT 旁白、AI 摘要、公众号模板文。

技术上精准，有观点，直接。幽默欢迎，但要服务内容，不是替代内容。用"我"和"你"，这是对话，不是论文。

## 禁用词

以下词语自动亮红牌：

- "首先……其次……最后……" — 直接说，不要结构词
- "值得注意的是" / "不难发现" / "显而易见" — 废话填充，删掉
- "赋能" / "驱动" / "赋予" — 说你实际的意思
- "无缝" / "流畅" — 没有什么是真正无缝的，描述具体体验
- "业界领先" / "最佳实践" — 展示，不要贴标签
- "在本文中，我们将探讨……" — 直接开始写
- "这不仅是……更是……" / "不是……而是……" — 很容易把普通事实强行拔高
- "从 X 到 Y" — 只有 X 和 Y 真有递进、覆盖或对比关系时才允许

## AI 摘要腔和模板腔

AI 辅助写作最常见的问题不是语法错误，而是写得太像一段正确但无用的摘要。以下写法要重写：

- 用宏大词替代事实：把"上线了一个命令"写成"开启了新的工作流范式"。
- 用形容词替代证据：写"显著提升效率"，但没有数字、场景或对比。
- 用整齐结构掩盖空洞：每段都很顺，但没有新的信息量。
- 用万能转折推进文章：每个小节都靠"同时""此外""值得注意的是"串起来。

不要为了去掉 AI 味，刻意加入轻微冗余、倒装、口头禅或错别扭表达。编辑部要的是具体、有来源、有判断，不是"伪装成人"。

写法优先级：

1. 具体细节优先于宏大判断。
2. 真实限制优先于漂亮结论。
3. 作者经验优先于泛泛共识。
4. 可验证来源优先于印象引用。

## 开头

前两句必须做到其中一件事：**点出问题** 或 **直接给结论**。不能是背景铺垫，不能是吹捧，不能从定义开始。

**好：**
> 上线前两周，我们砍掉了整个 metrics 产品。不是因为它不能用，而是因为预聚合的设计从根本上破坏了调试能力。

**不好：**
> 随着 AI 技术的快速发展，越来越多的工程师开始关注……

## 结构

按读者的心理问题组织，不按内部叙事：

1. **这解决什么问题？**（1-2 段，不要更多）
2. **底层怎么工作的？**（不是点哪个按钮，是技术原理；这是文章主体）
3. **有哪些权衡和备选方案？**（这条把好文章和普通文章分开）
4. **怎么用 / 下一步？**（具体可操作）

技术深度文章可以加：
- **踩过哪些坑？**（建立信任）
- **已知局限是什么？**（展示诚实）

## 标题

标题是文章里影响最大的一句话。要让目标读者在信息流里停下来。

**强标题**：提出具体主张，讲一个故事，或承诺具体收益：
- "上线前两周，我们砍掉了自己的 metrics 产品"
- "为什么我们的 AI Coding 工作流最终没用上 agent"
- "你的 JS bundle 里有 47% 的死代码，这样找到它"

**弱标题**：模糊的宣告：
- "关于 AI Coding 的一些思考"
- "我的 2026 年技术总结"

## 技术质量

**数字优于形容词。** 有性能主张就给数字：
- 不好："显著降低了延迟"
- 好："p99 延迟从 340ms 降到 45ms"

**代码必须能跑。** 包含 import、配置和上下文。注释解释*为什么*，不解释*是什么*。

**系统要有图。** 描述超过两个组件交互的系统，画架构图，用真实的名称，不用"组件 A"。

**诚实优于吹捧。** 承认局限，说清楚什么还不行。不夸大 AI 能力——"可能是根因"≠"找到了根因"。

事实核查和 AI 辅助写作风险参见同一 skill 目录中的 `ai-writing-quality.md`。涉及数字、引用、人物、论文、产品能力时，按该规范处理。

## 结尾

结尾给读者一个带走的认知，或指向下一步（文档链接、可以试的东西、可以给反馈的地方）。不要用"总结一下"重复全文，不要用"期待你的反馈！"收尾。

## 发布前自检

**内容：**
- [ ] 开头两句能让读者判断值不值得读
- [ ] 每个章节核心论点一句话能概括
- [ ] 所有抽象论点有具体案例支撑
- [ ] 性能数字有来源
- [ ] 代码能跑
- [ ] 没有"大家都知道"的废话段落
- [ ] 没有过度拔高、虚假范围、否定式煽情句
- [ ] 关键事实、引用、数据都有可追溯来源

**语言：**
- [ ] 没有禁用词
- [ ] 标题具体有主张
- [ ] 没有企业腔、AI 摘要腔、公众号模板腔
- [ ] 没有靠冗余、倒装、口头禅来伪装真人
- [ ] 结尾有落点，不是泛泛收尾

## 审校时

给反馈要具体：引用有问题的段落，说清楚为什么有问题，改写一版示范标准。不要只说"这里不够清晰"。
