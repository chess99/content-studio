# 内容制作

先看已有材料和用户要达到的效果，再选择交付形态。清晰的请求直接执行；只有影响核心内容、产品范围或发布授权的缺口才需要追问。

## 读取上下文

确定 `TOPIC_DIR`，向上找到内容资产仓库，读取其 `AGENTS.md` 和 `brand/BRAND.md`。主题已有文稿、设计、脚本时优先复用已确认内容。跨主题 `research/` 不自动成为创作输入。

运行 `python3 tools/workspace_doctor.py` 检查入口；缺少与本任务无关的工具不阻断工作。具体内容全部保存在外部内容仓库。创建目录与发布记录遵循该仓库规则。

## 选择交付

| 读者要完成的事 | 首选入口 | 关键判断 |
|---|---|---|
| 理解长论证、复现操作、评估产品 | `skills/longform-workflow/SKILL.md` | 保留证据、细节和可检索性 |
| 快速浏览若干观点或步骤 | `skills/image-post-workflow/SKILL.md` | 图片之间有明确推进，每张有独立信息任务 |
| 看清结构、因果或人物经历 | `skills/visual-storytelling/SKILL.md` | 信息图表达关系，漫画表达行动与变化 |
| 理解带数据与来源的口播知识 | `skills/knowledge-video-workflow/SKILL.md` | 事实追溯、实际配音时长、字幕对齐 |
| 看到产品操作、动态机制或经过剪辑的素材 | `skills/motion-video-workflow/SKILL.md` | 用真实画面和动作呈现结果 |
| 将已完成的文章放入公众号草稿 | `skills/wechat-publish/SKILL.md` | 用户明确要求创建草稿后执行 |

多个交付共用事实与原始素材，各自采用适合媒介的叙事。文章转视频时重新选择能被看见的动作；视频转图文时重新选择有信息价值的静帧。避免逐段搬运和为所有渠道生成相同内容。

## 执行与交付

- 在对话中简述选择与必要假设，然后完成已经明确的工作。无需让用户选择渲染库、目录名或内部角色。
- 多形态任务先做能检验核心表达的一份，再扩展其余交付；只修改确有差异的渠道版本。
- 中途反馈直接回到受影响环节。已确认的内容和不受影响的素材继续复用。
- 交付文件只放读者和下一位制作者需要的内容；提问、工作进度、工具限制和取舍讨论留在对话。可复现参数、信源和素材许可随工程保存。
- 最终说明完成的文件、可继续编辑的工程，以及实际检查过的范围。创建平台草稿、公开发布各自遵循明确授权。
