# 图文创作工作流

## 原则

先确定 `TOPIC_DIR` 并读取内容资产仓库根目录的 `AGENTS.md`。图文工作目录为：

```text
IMAGE_POST_DIR = TOPIC_DIR/image-post/
```

图文首先是传播产品，不是设计作品集。默认优先级为：

```text
读者问题 → 明确结论 → 关键证据 → 使用边界 → 视觉表达 → 品牌装饰
```

- 封面先回答“这篇讲什么、结论是什么、为什么值得点”，不要只制造氛围或悬念。
- 品牌识别不等于强制放作者名、Logo 和系列名；稳定配色、排版、人物、卡通角色、栏目标签或表达方式都可以形成识别。
- 卡片数量由独立信息价值决定，不按模板凑页数。知识、工具、模型和数据判断类内容默认优先尝试 3—5 张；超过 6 张时必须说明每一张不能合并或删除的理由。
- 每张卡片只承担一个明确任务；没有新增事实、判断、方法或决策价值的过渡卡直接删除。
- 按事实与视觉风险裁剪流程。不要为了“流程完整”制造无用文档，也不要把同一正文和图片按平台复制多份。

## 品牌上下文

从 `TOPIC_DIR` 向上定位内容资产仓库根目录 `CONTENT_ROOT`。开始写公开文案、规划图片或制作封面前，读取 `CONTENT_ROOT/brand/BRAND.md`。

`BRAND.md` 提供默认的表达与视觉边界，不是对每个主题的机械模板。优先级如下：

```text
用户本次明确要求 > topic.md 中的主题策略 > BRAND.md 默认规范 > 历史参考图
```

- 不自动搜索或读取 `CONTENT_ROOT/research/` 中的候选品牌方案。
- 作者名、Logo、系列名和品牌短句默认均为可选元素；只有它们能提升识别、信任或导航时才放。
- `CONTENT_ROOT/brand/COVER.md` 是封面策略与生产方法参考，不得把其中某一种技术路线当成所有内容的固定要求。
- 具体主题的最终图片写入 `IMAGE_POST_DIR/images/`，不得复制整套品牌文件。

## 风险分级

| 类型 | 例子 | 必需步骤 |
|---|---|---|
| 体验/氛围型 | 个人感受、AI 主视觉、单图故事 | 定位、文案、视觉检查 |
| 产品/证据型 | 工具发布、过程截图、实测记录 | 来源留档、隐私检查、证据与表述对应 |
| 数据/财经型 | 财富榜单、投资数据、对比图 | `research.md`、口径核对、逐项事实检查 |
| 多卡叙事型 | 观点轮播、教程、案例拆解 | `image-plan.md`、卡片价值检查、缩略图可读性检查 |

高风险要求可以叠加。用户只要求修改一张图或一段文案时，直接执行局部任务。

## 封面策略

先根据内容选择封面类型，不默认制作“工艺品式主视觉”：

| 封面类型 | 优先场景 | 首图应该交付什么 |
|---|---|---|
| 信息概要型 | 模型测评、工具推荐、数据判断、攻略 | 问题或对象 + 明确结论 + 2—4 个高价值点或限制 |
| 结果证据型 | 产品发布、实测、教程、案例 | 真实成品/截图/结果 + 一句关键发现 |
| 人物主体型 | 个人表达、访谈、IP、人设内容 | 稳定人物或角色 + 主题冲突/结果 |
| 场景情绪型 | 故事、摄影、猫、AI 影像、作品 | 一个强场景或动作；文字只保留必要钩子 |
| 品牌海报型 | 已建立强品牌认知、活动发布、用户明确要求 | 品牌资产作为点击理由，而不是装饰 |

知识与工具类首图允许直接承担“摘要卡”功能。不要把所有实质内容藏到后面，逼用户先滑动才能知道结论。

## 卡片精简规则

写 `image-plan.md` 前先给出：

1. 读者当前问题；
2. 一句话结论；
3. 收藏或转发理由；
4. 完成表达所需的最少卡片数。

对每张卡执行删除测试：

> 删除这张后，读者会失去哪一个独立事实、判断、方法或行动建议？

答不出来就删除或合并。以下内容通常不单独占一张：

- 仅重复封面结论；
- 只起承上启下作用；
- 为了展示流程而添加的背景知识；
- 正文一句话就能交代的免责声明；
- 与读者决策无关的完整研究过程。

## 流程

1. 在 `topic.md` 记录主题、目标读者、发布目的、读者问题、一句话结论、主栏目和渠道状态。
2. 按风险决定是否创建或补充根目录 `research.md`；原始证据放 `shared/`。
3. 写 `image-post/post.md`。标题、正文和标签可以放在同一文件中；正文不重复逐字朗读所有卡片。
4. 多图时写 `image-post/image-plan.md`，明确最少卡片数、每张图的独立价值、证据、顺序和可删除性；单图可以省略。
5. 按下节的生产路线选择整图模型生成、确定性排版、真实素材或混合制作。不要因包含中文、短数字、箭头或信息结构就自动退回程序化卡片，也不要忽略密集文字、精确数据和真实证据的容错要求。
6. 不强制整张模型生图，也不强制作者字标、Logo、系列名或页码。任何品牌元素都必须让位于标题、结论和证据。
7. 将最终发布图放入 `image-post/images/`，生图原稿或只属于本次图文的中间素材放 `image-post/source/`。
8. 按 `references/quality-gates.md` 完成事实、传播、视觉、隐私和发布检查。
9. 在 `topic.md` 记录各平台使用版本。只有发生实质差异时才创建 `image-post/xiaohongshu/`、`image-post/douyin/` 或 `image-post/wechat/`。

## 图片生产路线

先判断内容对**视觉完成度**和**事实精度**的要求，再选择生产方式：

| 方式 | 优先场景 | 门禁 |
|---|---|---|
| 图片模型整图生成 | 社交平台知识卡、观点图、比较图、决策图、强主视觉；需要整体构图、材质、图形与文字形成统一设计 | 文字可控、信息量适中；逐字检查生成结果 |
| 确定性排版 | 密集表格、长名单、财务数据、精确坐标轴、代码、真实 UI 复现 | 必须做视觉设计，不能只堆默认圆角框和普通 PPT 组件 |
| 真实素材 | 产品证据、过程、人物、实测结果 | 不伪造证据；保护隐私和权利 |
| 混合制作 | 同时需要强主视觉与高精度数据、截图或长文本 | 模型负责整体视觉或插画，确定性工具只负责不可容错部分 |

知识图文允许直接使用图片模型整张生成文字、图形和排版。模型生成的文字是**待核对的成品内容**，不能充当事实来源。若中文、数字或逻辑路径出错，优先对原图做单点编辑；连续两次仍无法修正，再缩短文案、拆图或切换混合制作。

对于 1—3 张、单张信息量为中低密度的社交知识图，默认先尝试图片模型整图生成，尤其是比较、决策、观点、流程和概念解释。不要仅因包含中文、短数字、箭头或分支就直接选择确定性排版。只有下列内容成为画面主体时，才优先确定性或混合制作：密集表格、长名单、代码、精确坐标图、真实 UI、连续小字号段落，或模型经过两轮定点修正仍无法通过文字门禁。

品牌色是可选素材，不是每篇内容的默认主题。每次根据主题、情绪、证据类型和用户反馈重新确定背景、主色和强调色；除非品牌规范明确要求，不要机械复用同一种纸色或流行的“AI 配色”。

不要把“确定性”误当成“设计完成”。出现下列特征时，默认重做视觉方向，而不是继续微调颜色：

- 暖黄或奶油色底仅用于制造所谓人文感，却与主题、品牌或用户要求无关；
- 多张等大的圆角白卡机械堆叠，层级只靠边框和阴影；
- 每张图使用相同栅格，只替换标题和正文；
- 标题、正文、图标和装饰互不参与构图，像程序输出或普通 PPT；
- 为了文字准确牺牲整体视觉，最终缺少缩略图吸引力。

## 模型整图流程

1. 在 `image-plan.md` 先确定每张图的唯一任务、信息上限和与前后图不同的结构。
2. 至少提出两个真正不同的视觉结构方向，并按主题选择其一；不要只在同一模板上换颜色。
3. 提示词写清画布、目标平台、视觉语法、构图、完整逐字文案、配色、禁止项和缩略图目标；不要只写“高级、好看、有设计感”。
4. 多图需要结构差异，例如对照、路径、证据、场景、时间线或矩阵；不能只换颜色和文案。
5. 每张图单独生成。把模型原稿保存到 `image-post/source/model-generated/`，最终裁切或缩放后的发布版保存到 `image-post/images/`。
6. 逐字核对标题、数字、专有名词、标签和路线逻辑。局部错误使用图片编辑做单点修正，并要求其他区域保持不变。
7. 检查原尺寸和目标平台缩略图；两者都通过后才进入发布目录。
8. 旧版需要保留时移入 `source/archive-vN/`，确保 `images/` 只存在实际发布顺序中的图片。

图片模型不可用或多次无法通过文字门禁时，改用混合制作或确定性排版。工具限制不应成为交付低完成度视觉的理由。

## 资产结构

```text
TOPIC_DIR/
├── topic.md
├── research.md                 # 按风险创建，可跨形态复用
├── shared/                     # 原始证据和跨形态素材
└── image-post/
    ├── post.md
    ├── image-plan.md           # 多图时可选
    ├── images/                 # 最终发布图
    ├── source/                 # 本次图文的原稿和中间素材
    ├── xiaohongshu/            # 仅保存平台差异
    ├── douyin/
    └── wechat/
```

不要保存 ZIP。不要覆盖原始素材。不要把 AI 生成的数字、引用或界面文字当作事实来源。
