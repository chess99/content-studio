# 图文创作工作流

## 硬原则

先确定 `TOPIC_DIR`，读取内容资产仓库根目录的 `AGENTS.md` 与 `brand/BRAND.md`。图文目录固定为：

```text
IMAGE_POST_DIR = TOPIC_DIR/image-post/
```

默认优先级为：

```text
读者问题 → 明确结论 → 关键证据 → 信息关系 → 视觉结构 → 事实核对 → 装饰
```

- 首图默认就是第一张有效内容，不另做只有标题、页码、气氛或品牌识别的封面。
- 卡片数量没有默认范围。用能完整表达的最少张数，两张讲清楚就只做两张。
- 每张图必须增加一个独立事实、判断、证据、方法或决策价值。纯过渡页、重复总结页和无信息 `1/4` 封面直接删除。
- 用户本次要求优先于主题策略和品牌规则。品牌文件只提供表达与事实边界，不提供固定模板。
- 不自动读取 `CONTENT_ROOT/research/` 或历史主题寻找视觉模板。历史成品只能在用户明确指定时作为参考。

## 风险与必要材料

| 类型 | 例子 | 必需步骤 |
|---|---|---|
| 体验或氛围 | 个人感受、角色、单图故事 | 定位、文案、视觉检查 |
| 产品或证据 | 工具发布、过程截图、实测 | 来源留档、隐私检查、证据对应 |
| 数据或财经 | ETF、价格、榜单、投资数据 | `research.md`、口径核对、逐项事实检查 |
| 多图叙事 | 教程、观点、案例拆解 | `image-plan.md`、删除测试、缩略图检查 |

高风险可以叠加。用户只要求局部修改时直接执行局部任务。

## 先设计信息关系

写 `image-plan.md` 前先回答：

1. 读者当前要解决什么问题。
2. 一句话结论是什么。
3. 什么内容值得收藏或转发。
4. 最少需要几张图。
5. 每张图唯一要呈现的关系是什么。

为每张图提出至少两个真正不同的视觉结构，再选择最能解释关系的一种。不要从“标题加几个卡片”开始。常见关系与结构见 `references/visual-design.md`。

视觉编码必须有事实含义。例如线路经过某站可以表示持有某类资产；没有精确比例时，不能用线宽、面积、液位或角度暗示权重。装饰不能承担事实。

对每张图执行删除测试：

> 删除这张后，读者会失去哪一个独立事实、判断、证据或方法？

答不出来就删除或合并。

## 选择生产方式

先看内容关系、视觉完成度和事实精度，再选工具。

| 方式 | 默认场景 | 门禁 |
|---|---|---|
| 图片模型整图 | 1—3 张中低密度知识图、财经比较、路径、决策、观点、场景化证据 | 完整逐字文案；逻辑关系写进提示词；逐项核对成图 |
| 真实素材 | 产品、人物、过程、结果、截图和实测证据 | 不伪造证据；保护隐私与权利 |
| 混合制作 | 强整体视觉加密集小字、精确图表或真实截图 | 模型负责统一视觉，确定性工具只承担不可容错部分 |
| 确定性制作 | 长名单、密集表格、代码、精确坐标轴、真实 UI 复现 | 必须说明为何模型或混合方式不适合；仍需完成真正的视觉设计 |

对于 1—3 张、中低信息密度的知识、比较和财经图，默认先用图片模型整图。中文、代码、短数字、箭头或分支本身不构成退回程序排版的理由。用户明确要求图片模型时直接使用。

确定性工具是精度方案，不是审美方案。出现等大圆角白卡、普通 PPT 栅格、表单感、标题与图形互不参与构图时，视为方向失败，重新设计结构。

## 工作流程

1. 在 `topic.md` 记录主题、读者、发布目的、问题、结论、栏目、风险和渠道状态。
2. 按风险创建或补充 `research.md`，原始证据放 `shared/`。
3. 写 `image-post/post.md`。正文补充图片，不逐字朗读图片。
4. 多图写 `image-post/image-plan.md`，记录最少张数、每张唯一任务、证据、两个视觉方向、选择理由和删除测试。
5. 按信息关系选择生产方式。使用图片模型时，每张图单独调用，不把多张不同任务塞进一次生成。
6. 原稿放 `image-post/source/`，最终发布图只放 `image-post/images/`。
7. 按 `references/quality-gates.md` 检查原尺寸与目标平台缩略图。
8. 在 `topic.md` 记录实际图片数量、顺序和渠道版本。只有内容实质变化时才建平台子目录。

## 图片模型整图

提示词必须写清：

- 用例、平台、画布比例和最终尺寸；
- 这张图唯一任务与目标读者；
- 视觉结构、阅读路径和每个图形的事实含义；
- 完整逐字文案与信息优先级；
- 配色与材质为什么适合当前主题；
- 禁止项、缩略图目标和不得添加的额外文字。

生成后执行：

1. 把模型原稿保存到 `source/model-generated/`。
2. 逐字核对标题、代码、数字、日期、专有名词、标签和结论。
3. 核对路线、箭头、图例、空间位置和因果顺序是否符合原始逻辑。
4. 局部错误优先做单点图片编辑，明确“只改这一处，其他内容保持不变”。
5. 连续两次单点编辑仍失败，再缩短文案、拆图或切换混合制作。
6. 适配目标尺寸时避免裁掉信息或明显拉伸；检查原尺寸与平台缩略图。
7. 被否定或废弃的版本移出 `images/`。最终目录只保留实际发布顺序中的图片。

用户认为结果丑、像 PPT 或方向错误时，不继续调颜色和阴影。提取反馈中的结构问题，废弃旧方向，重新提出至少两个构图方案并整图重做。

## 资产结构

```text
TOPIC_DIR/
├── topic.md
├── research.md
├── shared/
└── image-post/
    ├── post.md
    ├── image-plan.md
    ├── images/
    └── source/
```

不要保存 ZIP，不要覆盖原始素材，不要把 AI 生成的文字、数字、图表或界面当作事实来源。
