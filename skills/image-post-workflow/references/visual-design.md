# 信息关系与视觉结构

## 先找关系

设计从“读者需要看出什么关系”开始，不从卡片、图标、背景色或封面模板开始。

| 信息关系 | 优先尝试的视觉结构 | 适合表达什么 |
|---|---|---|
| 重合、缺失、混合 | 路线图、网络、集合、分子连接 | 产品成分、功能覆盖、参与者关系 |
| 阶段、因果、传导 | 产业链、接力、流水线、连续场景 | 研发到销售、输入到结果、问题到修复 |
| 时间变化 | 时间线、同一场景的状态变化、轨迹 | 版本演进、历史节点、前后变化 |
| 两类取舍 | 对照场景、天平、光谱、分叉路径 | 优缺点、适用对象、风险收益来源 |
| 多个对象的独特构成 | 指纹、样本架、剖面、坐标地图 | ETF、产品组合、模型能力、材料组成 |
| 真实证据支持判断 | 证据链、财报铭牌、实验记录、产品现场 | 测试结果、业绩数据、案例复盘 |
| 选择路径 | 决策树、岔路、控制台、筛选漏斗 | 条件判断、推荐边界、故障排查 |

这张表提供起点，不是模板。一个关系至少提出两个结构，再按可读性、事实风险和缩略图效果选择。

## 视觉编码边界

- 位置、连接、颜色、方向、大小和数量一旦形成规律，读者会把它理解为数据。
- 只有存在可核验数值时，才用面积、长度、线宽、液位、角度和密度表示比例。
- 没有精确比例时，用“经过或不经过”“出现或缺失”“归属哪一区域”等离散编码。
- 图例、线路、箭头和空间关系必须与文案一致，不能只负责好看。
- 实物隐喻要能解释内容。药瓶、芯片、仪表、票据、管道等元素若与信息无关，应删除。

## 财经与数据题材

财经准确性不等于程序排版。先把数字缩到真正影响判断的少数几项，再让它们进入视觉结构。

可复用做法：

- 比较多只基金的资产覆盖时，把资产类别设为站点，用线路表示经过与缺失；集中度、费率等精确数字放在线路终点，不用线宽冒充比例。
- 解释行情驱动时，把临床、授权、销售、订单和利润画成连续传导链，再把公司业绩放在对应阶段作为证据。
- 估值只需提示时，用温度尺、区间或少量并列数字，不额外制造一张密集估值表。
- 第一张承担比较，第二张承担证据与判断，两张都提供独立信息，不再加空封面。

## 结构失败信号

出现任意一项，优先换方向：

- 删除文字后，只剩背景、边框和装饰，看不出视觉中心或阅读路径。
- 多个同尺寸圆角框机械排列，内容只是换标题和数字。
- 每张图都使用同一栅格，只更换颜色。
- 图标、标题、正文和背景彼此独立，像把素材贴进 PPT。
- 为了品牌一致重复暖纸、奶油色、霓虹蓝、Logo 或作者字标。
- 画面很精致，但缩略图看不出主题、结论或值得点击的证据。
- 视觉比例暗示了资料并不存在的精确占比。

## 模型提示词骨架

```text
Use case: infographic-diagram
Asset type: [平台与第几张图]
Primary request: [唯一任务]
Canvas: [比例、尺寸、缩略图要求]
Information relationship: [重合、阶段、因果、选择或其他]
Visual structure: [路线图、产业链、证据场景或其他]
Reading path: [从哪里开始，怎样移动，在哪里结束]
Encoding rules: [位置、连接、颜色分别表示什么；哪些不能表示比例]
Text (verbatim): [完整逐字文案]
Hierarchy: [标题、结论、证据、口径的优先级]
Color and material: [与主题相关的选择]
Constraints: [代码、数字、逻辑、品牌与额外文字限制]
Avoid: [PPT、等大卡片、无关装饰、错字、乱码等]
```

多图分别写提示词。第二张必须使用与第一张不同、且更适合其任务的结构。
