# 动态视频制作

## 起点与路径

确定 `TOPIC_DIR`，读取内容仓库的 `AGENTS.md` 和 `brand/BRAND.md`。正式工程位于 `TOPIC_DIR/video/` 下；沿用已有工程结构，新建 HTML 工程使用 `video/project/`。产品仓库仅作素材与组件来源，视频制作不修改产品本身。

| 已有材料 / 目标 | 路径 |
|---|---|
| 软件仓库、真实页面、版本更新 | 读取 [产品演示](references/product-demo.md) |
| 自由动效、概念解释、动态信息图 | 读取 [HTML 视频](references/html-video.md) |
| 录屏、口播、实拍片段、已有成片 | 读取 [素材剪辑](references/footage.md) |
| 已有 Remotion / 其他视频工程 | 沿用其依赖和渲染链路；不为改字幕或时长迁移引擎 |

上游源码在 `vendor/`；只读取任务相关的技术参考。初始化路径、品牌入口、发布授权与本地工具以本工作区规则为准。无需执行上游推荐的全局安装、自动更新、账户用量查询、遥测反馈或云发布。

## 创作判断

从材料里提炼观众应记住的一件事，用能证明它的画面组织镜头。界面操作、物体变化、前后差异应承担主要表达，标题补充必要信息。数字、图表、功能状态与对比结果须有真实来源。

已有目标、渠道与参考足够时直接选一个合适方向。只有多个方向会实质改变表达且用户尚未表态时，提供少量有区别的候选。方向和制作参数可以保存在简短的 `video/brief.md`，已在现有脚本表达的信息无需另存一份。

先完成最能验证方向的一个镜头，再扩展全片。镜头长度由信息量、动作和实际声音决定。检查手机尺寸的阅读效果、转场前后连续性、首帧、最后一帧和声音落点。用户反馈方向有误时重做镜头表达，避免只调整装饰。

## 制作与验收

1. 先检查环境；新 HTML 工程使用 `apps/motion-video/README.md` 中的初始化工具。初始动效仅验证链路，交付前替换为本次内容。
2. 在 `video/project/` 内保存源文件、必要的本地媒体、字体及来源。外部服务按已有授权和费用范围使用；缺失凭证时先完成本地镜头与剪辑，不虚构生成结果。
3. 跑结构检查，再看关键静帧与转场。对含音轨的视频试听关键段落；无法试听时明确标注未验证项。
4. 在用户已要求成片的范围内完成本地渲染；已有脚本或预览审批约束继续遵守。用户只要求方向或预览时交付到相应阶段。
5. 使用 `tools/media_review.py` 核对成片参数并生成联系表。打开图片审查；自动检查通过只代表技术项通过。检查动态节奏需播放视频，不能用抽帧代替。
6. 最终成片与所需字幕、封面、发布文案放到 `video/publish/`。不同画幅重新取景、排字幕和检查，不把横屏内容简单挤进竖屏。

`check`、预览、渲染和媒体检查均为本地操作。公开发布和上传平台仍需本次任务中的明确授权。
